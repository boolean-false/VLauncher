# DEV-сборки VoxelCore

## Пользовательские сценарии

- **Новый профиль:** выбрать «DEV-сборка». Список загружается автоматически,
  предлагается последняя доступная сборка. Остальные сборки и SHA находятся в
  «Другие сборки и технические подробности». После подтверждения движок скачивается
  и создаётся профиль.
- **Установка или обновление модов:** сначала проверяется текущий движок. Если сервер
  требует новый коммит, лаунчер проверяет полный план с доступными DEV-сборками. Номер версии сам по себе не считается подтверждением совместимости.
- **Обновление движка:** «Управление → Обновить VoxelCore». Предлагается последняя
  совместимая доступная сборка. Автоматического обновления при запуске нет.
- **Применение DEV-сборки:** одно окно подтверждения предлагает полную
  копию профиля с мирами и настройками либо изменение исходного профиля. По умолчанию
  выбрана копия. После ошибки повторная попытка использует уже созданную копию.
- **Возврат на стабильную:** выбрать выпуск в управлении профилем. Проверяется состав
  модов; явный выбор стабильной версии не заменяется DEV-сборкой автоматически.
  Миры при смене версии и откате состава не восстанавливаются.

Для этих действий не нужно заранее включать режим в настройках. Просмотр и установка сборок
не меняют настройку показа списка. Подтверждение требуется при применении
DEV-сборки движка к профилю. Переключатель в настройках управляет показом ручного списка сборок в этом разделе.

Если совместимого артефакта нет, установка останавливается с объяснением.
Недоступность проверки на сервере не трактуется как отсутствие подходящей сборки.

Версия движка читается из `src/constants.hpp` выбранного коммита. Например,
`0.32` превращается в `0.32.0` и используется при проверке совместимости
контента.

## Доступ к сборкам

Список сборок, версия движка, проверка перед установкой и ZIP артефакта
запрашиваются через VSpace. Сервер обращается к GitHub со своим токеном;
метаданные списка кешируются на пять минут, версия закреплённого коммита - на час.
Сервер берёт последние 100 запусков из общего списка репозитория и локально
выбирает до 10 успешных push-запусков main для точного workflow. Отдельный
индекс workflow и фильтры GitHub не используются: они могут возвращать устаревшие запуски. Лаунчер не запрашивает и не хранит GitHub-токен.
Маршрут `/api/v1/mainline/metadata` принимает только фиксированные запросы
официальных workflows, артефактов и файла версии. Произвольные репозитории
и URL не поддерживаются.
Для сервера нужен `GITHUB_ACTIONS_TOKEN` с правом чтения Actions в
`MihailRis/voxelcore`.

## Какие сборки подходят

Лаунчер принимает только успешные `push`-сборки ветки `main` из
`MihailRis/voxelcore`.

| Система        | Workflow            | Артефакт           |
| -------------- | ------------------- | ------------------ |
| Linux x86_64   | `appimage.yml`      | `AppImage`         |
| Windows x86_64 | `windows-clang.yml` | `Windows-Build`    |
| macOS ARM64    | `macos.yml`         | `VoxelEngineMacOs` |

Проверяются репозиторий, workflow, commit SHA, ID артефакта, размер и SHA-256.
ZIP распаковывается с ограничениями на пути, симлинки и общий размер. На macOS
дополнительно проверяется архитектура бинарника.

Показываются до пяти последних доступных успешных сборок. Если workflow давно
не завершался успешно, список может содержать старые сборки; интерфейс показывает
дату последней и текущий SHA `main`. Старые артефакты GitHub со временем
удаляются, но уже установленная копия продолжит работать.

## Совместимость контента

Совместимость с VoxelCore задаётся для каждого релиза в Мастерской. Начальное
значение берётся из зависимости `base` в `package.json`, например
`base@>=0.32.0`. Если зависимости нет, поле заполняется вручную. Автор может
изменить найденное значение перед публикацией.

Когда минимальная версия VoxelCore ещё не выпущена, релиз можно привязать к
первому подходящему коммиту ветки `main`. Сборка выбирается из списка либо
задаётся полным SHA-1.

Ограничения хранятся в подписанных метаданных релиза. Исходный архив не
изменяется. При установке сервер проверяет, что выбранный коммит совпадает с
минимальным или является его потомком в официальной ветке
`MihailRis/voxelcore`. После выхода подходящей стабильной версии проверка
коммита больше не требуется.

Модпаки фиксируют точную стабильную версию VoxelCore и не поддерживают это
исключение.

## Профили

В профиле сохраняются SHA коммита, ID артефакта, хеш, платформа и версия движка.
Поэтому обновление ветки `main` не меняет уже созданный профиль само по себе.

Сборка привязана к ОС и архитектуре. При импорте профиля на другую платформу она
не заменяется автоматически. Откат версии движка также не откатывает мир, поэтому
эксперименты лучше проводить на копии профиля.

## Проверка

```bash
cargo test --manifest-path core/Cargo.toml --locked
cargo test --manifest-path src-tauri/Cargo.toml --locked
npm run build
```

Для проверки настоящего артефакта:

```bash
VLAUNCHER_REGISTRY_URL=https://vlauncher.space/api/v1 cargo run --manifest-path core/Cargo.toml --example check-mainline
```

Проверка использует временную папку и не меняет библиотеку пользователя.

## Перенос настроек между профилями

В «Управление → Настройки игры» можно импортировать настройки из другого профиля.
По умолчанию выбран только `controls.toml` (горячие клавиши); `settings.toml`
(графика, звук и остальные настройки движка) включается отдельно. Миры, моды и
файлы исходного профиля не меняются. Игра должна быть остановлена в обоих профилях.

Перед заменой выбранных файлов сохраняется резервная копия в `settings-backups`
целевого профиля. Действие «Отменить последний импорт» доступно и после перезапуска
лаунчера. Оно возвращает сохранённые настройки, включая отсутствие файла, если до
импорта его не было. Для разных версий движка показывается предупреждение о том,
что часть настроек может не поддерживаться.

Проверка списка через сервер без скачивания и установки:

```sh
VLAUNCHER_REGISTRY_URL=https://vlauncher.space/api/v1 cargo run --manifest-path core/Cargo.toml --example check-mainline -- --list-only
```

Стабильные выпуски и проверка выпуска перед установкой также запрашиваются через
VSpace (`/api/v1/engine/metadata`). Кеш общий для пользователей одного процесса API:
обновление по первому запросу после пяти минут, одновременные запросы объединяются.
При временном сбое GitHub успешный ответ доступен до суток; повторная попытка
обновления выполняется не чаще раза в 30 секунд. Кеш ограничен 256 записями
и очищается при перезапуске API. Отдельного фонового cron нет.
Архив стабильного выпуска скачивается по официальной ссылке GitHub без запроса
метаданных с IP пользователя.
