# Сборки VoxelCore из main

Эта функция находится в настройках в разделе «Экспериментальное» и по умолчанию
выключена. После включения нужно отдельно войти в GitHub. В списке версий
появятся успешные сборки ветки `main` с SHA коммита.

Версия движка читается из `src/constants.hpp` выбранного коммита. Например,
`0.32` превращается в `0.32.0` и используется при проверке совместимости
контента.

## Доступ к GitHub

Запросы к GitHub делает Rust, VSpace в них не участвует. Используется Device Flow
и публичный Client ID, Client Secret в приложении нет.

GitHub требует права `read:user public_repo` для скачивания артефактов Actions.
Право `public_repo` также разрешает запись в публичные репозитории, хотя
VLauncher использует его только для чтения. Это показывается пользователю до
входа. Доступ к приватным репозиториям не запрашивается.

Токен хранится отдельно от входа VSpace в системном хранилище паролей. Если оно
недоступно, токен остаётся в памяти до закрытия программы. Он не передаётся в
интерфейс, VSpace или временное хранилище GitHub. После выключения функции токен
удаляется с компьютера. Разрешение приложения можно полностью отозвать в
настройках GitHub.

## Какие сборки подходят

Лаунчер принимает только успешные `push`-сборки ветки `main` из
`MihailRis/voxelcore`.

| Система | Workflow | Артефакт |
| --- | --- | --- |
| Linux x86_64 | `appimage.yml` | `AppImage` |
| Windows x86_64 | `windows-clang.yml` | `Windows-Build` |
| macOS ARM64 | `macos.yml` | `VoxelEngineMacOs` |

Проверяются репозиторий, workflow, commit SHA, ID артефакта, размер и SHA-256.
ZIP распаковывается с ограничениями на пути, симлинки и общий размер. На macOS
дополнительно проверяется архитектура бинарника.

Показываются пять свежих сборок. Старые артефакты GitHub со временем удаляются,
но уже установленная копия продолжит работать.

## Совместимость контента

Совместимость с VoxelCore задаётся для каждого релиза в Мастерской. Начальное
значение берётся из зависимости `base` в `package.json`, например
`base@>=0.32.0`. Если зависимости нет, поле заполняется вручную. Автор может
изменить найденное значение перед публикацией.

Когда минимальная версия VoxelCore ещё не выпущена, релиз можно привязать к
первому подходящему коммиту ветки `main`. Сборка выбирается из списка либо
задаётся полным SHA-1.

Ограничения хранятся в подписанных метаданных релиза. Исходный архив не
изменяется. При установке сервер проверяет, что выбранный коммит совпадает с
минимальным или является его потомком в официальной ветке
`MihailRis/voxelcore`. После выхода подходящей стабильной версии проверка
коммита больше не требуется.

Модпаки фиксируют точную стабильную версию VoxelCore и не поддерживают это
исключение.

## Профили

В профиле сохраняются SHA коммита, ID артефакта, хеш, платформа и версия движка.
Поэтому обновление ветки `main` не меняет уже созданный профиль само по себе.

Сборка привязана к ОС и архитектуре. При импорте профиля на другую платформу она
не заменяется автоматически. Откат версии движка также не откатывает мир, поэтому
эксперименты лучше проводить на копии профиля.

## Проверка

```bash
cargo test --manifest-path core/Cargo.toml --locked
cargo test --manifest-path src-tauri/Cargo.toml --locked
npm run build
```

Для проверки настоящего артефакта:

```bash
VLAUNCHER_GITHUB_TOKEN=... \
cargo run --manifest-path core/Cargo.toml --example check-mainline
```

Не вставляйте этот токен в issue или лог. Проверка использует временную папку и
не меняет библиотеку пользователя.
